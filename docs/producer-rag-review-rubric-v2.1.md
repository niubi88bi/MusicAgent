# Producer 制作方案文本盲评口径（v2.1）

> v2.1 继承 `docs/producer-rag-review-rubric.md` 的全部定义，只新增“明确硬要求违反”。既有 v2 评价保持原样，不追溯改分。

## 新增字段：明确硬要求违反

当制作方案与用户明确写出的必须、禁止、唯一或替代要求冲突时，标记 `hard_requirement_violation=true`。常见情形包括：

- 用户写“不要钢琴”，方案仍使用钢琴；
- 用户写“用木吉他替代钢琴”，方案没有木吉他；
- 用户写“全程无人声”，方案加入人声、口白或人声采样；
- 用户指定女声，方案改成男声；
- 用户禁止说唱或 MC，方案仍加入相关人声。

该字段与另外两项分开：

- `over_constraint`：方案把非必要选择写成不可替换的强制实现；
- `unsupported_expansion`：方案新增输入不能支持的方向、角色、曲风或叙事；
- `hard_requirement_violation`：方案直接违反明确要求。

同一问题可以同时触发多个字段，但评审者必须分别说明理由，不能为了表达“严重”而随意勾选。

## 偏好规则补充

存在明确硬要求违反的方案原则上不能胜过没有该问题的方案。若两份方案都违反同一核心硬要求，应优先判为“两者均不合格”；只有在需要继续排序时，才比较其他维度，并明确说明胜者仍不可直接使用。

## 当前适用范围

v2.1 先用于显式制作约束保护的影子实验，不改变正式 Producer、LangGraph、Web 或 RAG 路由。
