# 韵脚词 RAG 必要性审计

> 日期：2026-09-13  
> 结论状态：现有证据不支持首稿默认注入韵脚词；“失败回炉时条件触发”仍是假设，需先与更轻量的固定辙部说明做小型对照实验。

## 1. 本次要回答的问题

本审计只判断“是否有必要让 RAG 向作词模型推荐韵脚词”，不判断风格卡 RAG。检查不修改作词提示词、不安装 ChromaDB/BGE、不调用 DeepSeek 或 HeartMuLa，也不把规则分当作自然度证据。

## 2. 当前链路事实

- 作词提示词只把 `target_rhyme_group` 名称放入结构化需求，并要求“尽量自然使用该辙口”，没有告诉模型该辙包含哪些韵母或示例词。
- 十三辙与韵母的确定性映射已经存在于 `tools/lyrics_quality/thirteen_rhymes.py`，因此“解释辙名”不需要向量检索。
- 390 个候选目前全部为 `draft`；主题标签填充 0/390、情绪标签填充 0/390、常用度填充 0/390、批准 0/390。它们当前只能按辙部过滤，尚不能进行有证据的主题/情绪排序。

## 3. 无 RAG 历史证据

### 3.1 D9.4 新主题源池

对 `data/output/evaluations/d9-4-source-pool/` 的 12 个自然主题、双 persona 共 24 份真实 DeepSeek 草稿，用当前规则重新评分：

- 完整规则通过 15/24；押韵分达到 70 分门槛 16/24；平均押韵分 74.6。
- 所有可分析行对指定目标辙的命中率为 64.8%。结构型 persona 为 69.4%，意象型为 60.4%。
- 按双候选家族计算，10/12 个主题至少有一份候选达到押韵门槛；只有 `comeback-rock` 和 `summer-storm-dancepop` 两个主题的两份候选都低于押韵门槛。
- 9/12 个主题至少有一份候选通过完整规则；`late-cafe-jazz` 的失败来自结构门槛而非押韵不足。

这说明无 RAG 的双候选机制多数时候已经能提供一份押韵合格候选，不支持把韵脚词注入设为每次首稿的默认步骤；但仍存在少量双候选同时偏离目标辙的场景。

### 3.2 既有自然工作流试点

现存 8 个已完成的自然工作流样本覆盖 3 个主题，8/8 都在首轮通过，押韵分均不低于 70，没有触发回炉。另有 3 个失败样本分别来自空响应、非法 JSON 和 Hook 契约错误，不是押韵失败。

这些样本重复主题较多，不能证明普遍不需要辅助，但没有提供“必须默认上韵脚 RAG”的运行证据。

## 4. 根因更像辙名知识缺失，而不是词汇不足

两个失败草稿的创作说明暴露了直接证据：

- `comeback-rock/structured` 声称“点、茧、怯、纹、问、燃”属于中东辙，实际分属言前、乜斜和人辰；目标辙命中率只有 1/30，押韵分 26.0。
- `unsent-apology-rnb/structured` 把“指头、暗掉、偏旁、前往”描述为中东辙，实际分属由求、遥条和江阳；押韵分 56.0。

模型能写出大量自然句尾词，却不能可靠解释“中东”等传统辙名。因此第一干预应是把确定性映射随需求传入，例如“中东：eng/ing/ong/iong”，再给少量示例；这比建立 390 词向量库更直接、更可解释。

## 5. 当前结论

1. **不建议首稿默认注入韵脚词 RAG。** 10/12 个新主题已经能由双候选至少提供一份押韵达标稿，默认注入会增加提示长度、套词和陈词滥调风险。
2. **有必要补充目标辙的确定性说明。** 这是当前最直接、成本最低的修复方向，不需要 ChromaDB。
3. **条件触发的韵脚候选仍值得小试，但尚未证明必要。** 它只能放在“两份首稿都低于押韵门槛”或明确回炉的路径，不应在首稿常驻。
4. **暂缓精审全部 390 词。** 先从一个目标辙选少量词完成对照实验；只有候选词相对“映射说明”表现出额外收益，才值得继续审核和建立正式词库。

## 6. 最小对照实验建议

使用现有两个双候选押韵失败主题的 4 份原始草稿，不重新生成首稿。每份草稿分别执行三种回炉提示，共 12 次 DeepSeek 调用：

- A：现有规则反馈，不补辙部知识。
- B：现有反馈 + 中东辙确定性韵母说明 + 3～5 个通用示例。
- C：B + 8 个经过人工确认、与主题相关的中东辙候选词。

固定源草稿、模型、温度、最大 token 和回炉指令；保存请求、响应与规则报告。匿名比较：

- 目标辙行命中率、押韵分、是否跨过 70 分门槛。
- 原意保留、句尾自然度、是否出现为了命中候选而改写整段。
- 候选词直接复制数量与重复程度。

只有 C 相比 B 在至少 3/4 份源草稿上表现出额外的目标辙改善，并且人工自然度不下降，才进入“回炉时条件检索”的实现讨论。若 B 已能稳定修复，取消韵脚词 RAG，仅保留确定性映射和规则反馈。该试点只覆盖中东辙，结果只能作为是否继续研究的门槛，不能外推十三辙整体效果。

## 7. 证据边界

- 24 份源池草稿只覆盖中东、江阳、怀来 3 个辙部，不覆盖全部十三辙。
- 规则分只反映当前确定性押韵/结构口径，不等于歌词自然度、可唱性或音频效果。
- 现有 D9.4 人工标注关注句长和停顿，不是韵脚词自然度标注，不能拿来替代本实验的匿名自然度比较。
- 本审计没有运行 RAG-on 样本，因此“候选词会改善结果”仍是待验证假设。

## 8. 第一阶段实际结果（2026-09-13）

用户确认后先执行了 A（现有规则反馈）与 B（固定辙部映射）两组，不提前运行候选词 C。4 份锁定源稿共完成 8 次真实 DeepSeek 改写，8 次底层 API 尝试均成功且没有重试。

- A 为 0/4 押韵过线，平均押韵分 43.7、目标辙命中率 25.8%。
- B 为 2/4 押韵过线，平均押韵分 60.2、目标辙命中率 48.9%。
- B 的平均改动行数由 A 的 5 行增加到 10 行，并出现多处硬押表达。

B 有方向性收益，但没有达到 3/4 门槛；匿名自然度复核仍待人工完成。此外，B 提示中的“保留原 Hook”与部分原 Hook 本身不属目标辙发生冲突，当前结果不是固定映射能力的干净上限。暂不进入候选词 RAG；详细结果与后续修正建议见 `docs/rhyme-assistance-stage1-results.md`。

## 9. B2 修正复验（2026-09-14）

复用原 A 基线，只补跑 4 次允许修正错误 Hook 句尾的 B2。4/4 调用成功、无重试；B2 仍只有 2/4 押韵过线，平均押韵分 59.6、目标辙命中率 47.8%、平均改动 11 行，未达到 3/4 门槛，也没有优于原 B 的总体结果。

本轮进一步定位到 `format_revision_feedback()` 只保留前 8 条问题。长歌词的反馈先被 Verse 错行占满，两个结构型 B2 输出均把 Verse 提升到较高命中，却让 Chorus 和 Bridge 保持 0 命中。因此当前先暂停候选词 C；增加数据源或词库不能解决反馈覆盖缺口。是否改为“分段均衡反馈”以及目标辙应约束哪些段落，属于方法层调整，需另行确认。
