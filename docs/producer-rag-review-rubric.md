# Producer 风格 RAG 文本盲评口径（v2）

> 状态：自下一批新案例起使用。既有人工与网页模型评价保持原样，不按本口径追溯改分。

## 1. 评价对象与边界

本量表只评价 Producer 输出的文字制作方案，不评价最终音频、可唱性或 HeartMuLa 对提示词的实际跟随能力。评审者只能看到用户请求、结构化需求、歌词或器乐结构，以及匿名的 X/Y 方案；不得根据文风猜测是否使用 RAG。

## 2. 三项评分

- **风格/需求契合度**：是否正确落实用户明确指定的曲风、情绪、结构、人声和负向约束。
- **制作可执行性**：制作人是否能据此安排节奏、音色、人声和段落动态；细节多不等于必然更高分。
- **内部一致性**：风格、乐器、人声、歌词意象和段落推进是否互相支持，是否出现自相矛盾。

三项均使用 1～5 分。偏好必须综合三项评分与问题标记，不允许只因文本更长或参数更多而选择。

## 3. 合理实现、无依据扩写与过度约束

### 3.1 合理实现

满足下列条件的风格原生制作细节，属于对已知需求的合理实现，不自动记为“无依据扩写”：

1. 能由用户明确曲风、组合关系、歌词意象或已批准风格卡直接推出；
2. 不改变用户的人声、语言、叙事主体、段落功能或曲风主次；
3. 以建议性制作语言表达，仍给制作人保留调整空间。

例如，明确要求 Future Bass + Trance 且指定“Trance 长线铺陈、Future Bass 只在副歌释放”时，four-on-the-floor、长 build、supersaw、808 可作为合理落地手段；它们本身不构成扩写。

### 3.2 无依据扩写

只有在方案引入了无法由输入支持、并实质改变歌曲方向的内容时标记，包括：

- 擅自改变歌手性别、人声类型、语言或是否说唱；
- 把 Bridge 两句说唱扩展为全篇说唱；
- 新增无关叙事、角色、场景或风格主轴；
- 加入与用户硬约束冲突的内容。

项目级安全或生成规范（例如不引用真实艺人）不计作用户需求层面的无依据扩写，但应与制作描述分层呈现。

### 3.3 过度约束

细节方向合理，但在用户没有要求且不存在唯一正确答案时，被写成必须遵守、不可替换的参数或实现，即标记为过度约束。判断重点是“是否锁死实现空间”，不是“是否出现 BPM、乐器或混音术语”。

例如，“约 140 BPM，可按旋律微调”通常是参考；“必须 142 BPM，不得偏离”才是强约束候选。若某细节是用户硬要求或组合风格成立的必要边界，则不因具体而自动扣分。

## 4. 术语规范

- 中文声乐术语“混声”统一解释为 `mix voice` 或 `chest-head mix`。
- 除非用户明确要求男女合唱，不得写成 `mixed-gender vocal`。
- “女声吟唱为主、Bridge 最多两句短说唱”应同时检查主导人声与局部说唱上限，不能只检查是否出现说唱。

## 5. 偏好与决定性问题

如果评审者选择了三项总评分更低的一方，必须指出一个“决定性问题”，并说明该问题为何足以覆盖分数差。决定性问题只能来自明确需求冲突、关键不可执行、内部逻辑错误、过度约束或无依据扩写，不能只写“更保守”“更简洁”。

允许平局。差异仅是同方向的可替换制作选择，且没有决定性问题时，不应强行选边。

## 6. 多模型汇总规则

- 每个模型先独立盲评，再按密钥解码；网页模型名称和版本不可确认时必须记录为未知。
- 多数偏好只表示该样本上的跨模型方向，不等于正确率、统计显著性或生产准入。
- 评分分歧与问题标记分歧分别统计；不能用多数票抹去少数模型指出的系统性风险。
- 旧评价不按新量表追溯改写。新量表先用于新案例，观察评审一致性是否提高后再决定是否作为长期准入协议。

## 7. 当前准入边界

本口径的确认不改变正式 Producer、LangGraph、Web 路由或 RAG 默认状态。现有证据仍只支持继续做本地演示范围的新案例文本验证；是否进入 opt-in 运行时，需要新的预登记案例和按本量表完成的盲评结果。
