## 3. 自然度与改写幅度风险

自动过线的映射稿仍出现明显硬押，例如“第三次摔的重”“终点灯”“落了一层空”“散场中”。这说明更高的目标辙命中率可能是通过牺牲句子自然度得到的。B 的平均改动行数也是 A 的两倍，表明当前约束会推动模型大面积改写。

匿名材料已写入 `blind_review.md` 与 `blind_review_cards.json`，候选身份保存在单独的 `blind_review_key.json`。在人工复核完成前，不能把自动分改善写成歌词质量改善。

## 4. 本轮发现的实验限制

1. 每个条件每份源稿只有一次随机采样，结果只能用于筛查，不具备统计显著性。
2. 本轮只覆盖中东辙，不能外推到十三辙整体。
3. B 的补充说明包含“保留原 Hook”。部分原 Hook 本身不属于中东辙，这会与“提高所有目标辙行命中”形成冲突；一份通过稿实际改写了 Hook。当前 2/4 可能低估纯映射的修复能力，也使 B 不再是完全纯净的知识增量对照。
4. 当前规则在指定目标辙时会对 Verse、Chorus、Bridge 的全部可分析行计算同辙命中；这比现代歌曲常见的段内押韵约束更强，可能是大面积硬改的上游原因。这个观察不等于规则应立即修改，规则口径变更仍需单独设计和批准。

## 5. 当前建议

先完成 4 组 X/Y 匿名人工复核，不审核 390 词、不接 RAG。若人工结果确认映射稿的自然度明显下降，先不要做“候选词是否优于映射”的第二阶段；应先复用本轮 A 基线，只补跑 4 次去除 Hook 冲突的纯映射 B2，确认固定映射本身的真实上限。

只有在 B2 仍无法稳定修复、且自然度风险可控时，才值得用少量人工主题词测试候选词是否有额外收益。即使进入候选词阶段，也只能验证失败回炉时的条件辅助，不支持首稿默认注入。

### 7.1 新定位的上游问题

`format_revision_feedback()` 当前只输出 `report.issues[:8]`。四份 B2 提示都恰好只有 8 条问题；长歌词按当前问题顺序先列 Verse 的弱押韵与错行，后面的 Chorus、Bridge 逐行问题没有进入反馈。

这与 B2 输出高度一致：

- 复出摇滚结构型：Verse 中东命中 7/12，但 Chorus 0/14、Bridge 0/4。
- 暴雨舞曲结构型：Verse 8/8，但 Chorus 0/14、Bridge 0/2。
- 两个意象型过线稿也都保留了 Bridge 0 命中，并出现“誓盟”“家中”“散场空”等硬押。

这些分段数字受现有解析器不识别 `[Outro]` 的限制：尾声会沿用前一段标签。因此它们只用于定位反馈覆盖，不作为自然度或最终段落质量证据。

### 7.2 更新后的判断

Hook 冲突不是主要瓶颈，固定映射本身也没有达到 3/4 门槛。当前不能进入候选词 C 或审核 390 词，因为增加词库不会自动修复“反馈只覆盖前 8 条”和“目标辙是否约束所有段落全部行”这两个更前置的问题。

下一步应先讨论并批准回炉反馈的覆盖策略：至少让每个 Verse、Chorus、Bridge 都得到段级命中率和有限代表错行；同时单独判断目标辙应约束 Chorus、每段主导韵，还是当前的全行目标。该调整属于评估口径和回炉方法变化，本轮未实施。
